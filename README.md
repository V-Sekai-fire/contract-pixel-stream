# pixel-stream

A frame protocol for streaming a Godot render over WebTransport, specified in Lean 4 and bound to its implementation by conformance vectors.

## What this is

Three parts of a pixel streamer already exist in `entities-godot`: QUIC and
WebTransport (`modules/http3`), CineForm encode and decode (`modules/cineform`),
and async GPU readback (`servers/movie_writer`). What did not exist is the
agreement about bytes between them — how an encoded frame is cut into
datagrams, which fragments may be lost, and when a frame may be presented.

This repository is that agreement. It ships no service.

- `PixelStream/` — the Lean 4 model and its proofs.
- `include/pixel_stream/` — the C++ side: the wire header and a header-only
  reassembler. The engine module includes these rather than mirroring them, so
  there is one implementation and nothing to drift.
- `vectors/corpus.txt` — delivery traces with the model's expected output,
  generated by `lake exe wire_vectors`.
- `proof/` — replays the corpus through the C++ and carries the controls.

## What is proved

`Reassembly.lean`

- **monotone emit** — presented frame numbers strictly increase, so a fragment
  arriving late cannot resurrect a frame already superseded.
- **no partial presentation** — a frame is emitted only when every declared
  fragment has arrived. This is the anti-tearing property.
- **bounded buffer** — at most `capacity` incomplete frames are held, so a
  sustained loss burst cannot grow memory without limit.

`Admission.lean`

- **no half-sent frame** — the wire takes every fragment of a frame or none.
- **live memory bounded** by the encoder pool depth plus the send queue depth.
- **drain progress** — a non-empty send queue strictly shrinks.

`Echo.lean`

- **echo never exceeds the client's input** — so the client can compute the true
  age of the image it is looking at, which is what makes the latency
  measurement a measurement rather than a proxy.

`Codec.lean`

- **a frame is never presented when a declared dependency was dropped**, for any
  GOP structure.

## What is not proved, on purpose

**Bounded end-to-end latency.** There is no clock, no network and no encoder
timing in the model. Any bound would be a bound on invented constants, and it
would later be quoted as though it were about the system. Latency is measured,
not proved.

**Input-to-frame causality as such.** "The server rendered after consuming input
k" is a claim about C++ that Lean cannot discharge here. The provable part —
echo monotonicity — is in `Echo.lean` instead.

**The intra-only decodability instance is trivial.** With CineForm every frame
is independent, so `Codec.lean`'s theorem does no work. It is written
GOP-parameterized so that it already covers an inter-frame codec if the codec
question below is answered that way; today it earns its place only as
scaffolding, and pretending otherwise would be decoration.

## What was measured

Toolchain: Lean 4.30.0, Plausible at `a456461`, MSVC 14.44.35207, CMake 4.4.3,
Windows 11 26200.

| check | result |
| --- | --- |
| `lake build` | 6 modules, 0 `sorry`, no warnings |
| model vs its own expectations | 8 of 8, checked at build time by `native_decide` |
| C++ vs the Lean corpus | 8 of 8 traces agree |
| broken-reassembler control | refused by **7 of 8** traces |
| missing-corpus control | exits 1, does not pass quietly |
| falsification search | 4000 candidate traces, `provablyNone` |
| search falsifiability control | the broken reassembler caught at candidate 0 |

The control is refused by 7 of 8 rather than 8 of 8, and the exception is worth
stating: `two-frames` gives every frame a single fragment, so a reassembler that
emits on the first fragment is accidentally right. That is the argument for
keeping multi-fragment and malformed traces in the corpus — against a
single-fragment corpus this gate would certify the defect.

## The falsification search, and why not the `plausible` tactic

`lake exe falsify` searches for a delivery trace that breaks monotonicity,
provenance or uniqueness, using `plausible-witness-dag`'s `resolve` ladder. It
runs as a program, so nothing is admitted.

The `plausible` TACTIC is deliberately not used. It searches for a
counter-example and, finding none, closes the goal with `sorry`. Three
properties were written that way first: they built cleanly, reported "unable to
find a counter-example", and left three admitted declarations behind, which
exports a tested guess as a proven fact.

Two details of the harness are worth stating rather than implying:

- **A budget hit is a failure, not a pass.** `resolve` reports `budgetHit`
  separately from `provablyNone`, and `Falsify.lean` treats an exhausted search
  as a failing run. An unmet precondition is a FAIL.
- **The search width is the readback's, not the ladder's.** `resolve` decides
  the outcome from the deterministic readback and discards `certify`'s return,
  so the number that matters is the 4000 candidate traces the readback walks,
  not the ladder's `finBound`.

The search carries its own control: the same query is run against a reassembler
that emits on its first fragment and must catch it, which it does at candidate 0.

The lesson generalised into the gate. Grepping sources for `sorry` would not
have caught the tactic, because no source said `sorry` -- the tactic introduced
it. CI now reads the compiler's own `declaration uses 'sorry'` warning as well.

## Known gaps

- **The codec is not chosen.** CineForm is an intermediate codec: RFD 1137
  measured 0.47 Gbit/s at 1080p60. At 1200-byte datagrams that is roughly 1250
  datagrams per frame, and with no FEC one lost datagram destroys the frame — at
  0.1% loss, most frames die. Whether video rides datagrams at all, or one
  reliable QUIC stream per frame, is an open question that a measurement should
  answer, not this README.
- **No real-time frame source yet.** `MovieWriter` runs the engine in offline
  movie-maker mode with a fixed timestep. Streaming needs wall-clock stepping.
- **No encode sink yet.** `MovieWriterCineForm` writes to an MKV muxer; nothing
  emits a frame to a socket.
- Audio is out of scope for now. The presence loop is out of scope permanently
  — see RFD 1170, which argues a loop whose purpose is two people seeing each
  other should not round-trip every frame through a server. The targets here are
  thin clients, headless render farms, remote preview and CI screenshotting.

## `contract-http3-queue` is required but deliberately not placed

`lakefile.toml` requires it by git URL rather than through the goal manifest.
That is a decision, not an oversight: `default.xml` carries no comments, so a
reader cannot tell absence from omission, and this paragraph is where the
difference is recorded. It models the transport layer below this one — the
inbound queue and the wake loop. The boundary is that `http3-queue` owns inbound
delivery and this repository owns outbound admission and frame reassembly.

## Building

    lake build                       # proofs
    lake exe wire_vectors > vectors/corpus.txt
    cmake -S . -B build && cmake --build build
    ./build/vector_replay vectors/corpus.txt
